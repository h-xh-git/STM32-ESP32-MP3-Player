## 0. 执行摘要

本规划书在四项前提已确认的基础上编制：

| 项目 | 已确认结论 |
|---|---|
| 硬件形态 | 立创天空星 STM32F407VET6 核心板 + 外接 ST7789 2.4寸 SPI 屏 + MAX98357A + 独立按键 |
| 存储 | 使用核心板**板载 TF 卡座**（SDIO 4-bit，硬连 PC8–PC12 / PD2） |
| 架构分工 | 保持计划书分工：STM32 管 SD+FATFS+UI+按键，ESP32-S3 管 MP3 软解 + I2S |
| 引脚 | 全部重新设计，见第 2 章（旧工程引脚一律不受限） |

**一句话方案**：STM32F407 用 SDIO 4 位 + FATFS 读取 TF 卡上的 MP3 压缩码流，经 USART2 @ 1 Mbps 按"信用窗口"协议推送给 ESP32-S3；ESP32-S3 在 8 MB OPI PSRAM 中建立 512 KB 播放缓冲，用 Helix 定点解码器解出 16 bit 立体声 PCM，经 I2S 送 MAX98357A 驱动 8Ω 喇叭；STM32 侧同步驱动 320×240 播放器界面与 5 个按键。

**关键量化指标**：

| 指标 | 设计值 | 说明 |
|---|---|---|
| 链路速率 | 1 Mbps（可升 2 Mbps） | USART2 挂 APB1 42 MHz，BRR=42 **分频误差 0** |
| 链路吞吐 | 约 95 KB/s | 320 kbps MP3 仅需 40 KB/s，余量 **2.4 倍** |
| 音频块 | 1024 B / 帧 | 帧开销 8 B，效率 99.2% |
| 播放缓冲 | 512 KB PSRAM | 目标水位 384 KB，实测水位应不低于 32 KB |
| 启动时延 | 上电 → 首声 ≤ 3 s | 含扫卡、填缓冲 64 KB |
| 按键响应 | UI ≤ 50 ms / 出声 ≤ 300 ms | 切歌 ≤ 500 ms |
| 连续播放 | 60 分钟零断音 | 验收项 AC3 |

## 2. 硬件引脚设计（全新）

### 2.1 设计原则

1. **总线最优**：高速外设挂 APB2（SPI1 / USART1 / TIM8）；链路串口挂 APB1 但选分频可整除的引脚组。
2. **端口聚合**：同一功能集中在同一 GPIO 端口，便于 BSRR 原子写入与位带操作。
3. **独占 SDIO**：PC8–PC12 + PD2 六个脚被 SDIO 完全独占，其他功能一律让开。
4. **避开板载固定占用**：晶振（PC14/PC15）、USB（PA11/PA12）、SWD（PA13/PA14）、BOOT1/LED（PB2）、板载用户键（PA0）、SWO（PB3）。
5. **每项留 Plan B**：焊接或飞线异常时可平行替换（见 2.7）。
6. **预留 P2 扩展**：编码器、蜂鸣器占脚但**不占用关键资源**，P1 可不焊。

**电源方案**：推荐 5 V / 2 A 单电源适配器分三路供电——STM32 核心板一路、ESP32-S3 一路、MAX98357A 一路。功放峰值电流可达 650 mA，务必给足不低于 800 mA 的余量；VIN–GND 就近并 **470 µF 电解 + 0.1 µF 陶瓷**。

## 3. MAX98357A 音频输出设计

### 3.1 引脚判据（已核实）

**GAIN 引脚（决定增益，改动后需重新上电）**：

| 增益 | 接法 |
|---|---|
| 15 dB | 100 kΩ 电阻接 GND |
| 12 dB | GAIN 直接接 GND |
| **9 dB** | **悬空（默认，本方案采用）** |
| 6 dB | GAIN 直接接 Vin |
| 3 dB | 100 kΩ 电阻接 Vin |

**SD / MODE 引脚（三态，同时决定关断与输出声道）**：

| SD 电压 | 行为 |
|---|---|
| 低于 0.16 V | **关断（硬件静音）** |
| 0.16 V – 0.77 V | 输出 **(L + R) / 2**，立体声平均值 |
| 0.77 V – 1.4 V | 只输出右声道 |
| 高于 1.4 V | 只输出左声道 |

**关键细节**：SD 脚内部有 **100 kΩ 下拉**。Adafruit 官方模块另在 SD 与 Vin 之间加了 1 MΩ 上拉，使其在 5 V 供电时默认落在"立体声平均"区。

### 3.2 推荐电路（同时获得硬件静音 + 真单声道混合）

| 参数 | 取值 |
|---|---|
| AMP_SD 驱动脚 | ESP32 GPIO8 |
| 串联电阻 | **560 kΩ**（GPIO8 → SD 节点） |
| SD 节点对地 | 模块内部 100 kΩ 下拉 |
| GPIO8 输出高 (3.3 V) | SD ≈ 3.3 × 100 / (100 + 560) = **0.50 V** → 落在 0.16–0.77 V → **(L+R)/2 单声道混合** |
| GPIO8 输出低 (0 V) | SD ≈ 0 V → **关断静音** |

**收益**：用一个 GPIO 同时实现①上电/切歌/暂停的硬件级静音（反爆音最有效的手段）②立体声下混为单声道，避免"只出左声道丢失右声道信息"。

**注意事项**：
- 若使用 Adafruit 款模块（SD–Vin 间自带 1 MΩ），必须**先断开该 1 MΩ**，否则电平被抬到不低于 0.77 V 变成只出右声道。
- ESP32 上电/复位期间 GPIO8 为高阻，此时 SD 电平不确定——因此**必须在固件最早阶段把 GPIO8 配置为推挽输出低**（早于 I2S 初始化）。
- 若模块无法改造，退路是 SD 直接接 Vin（只出左声道），或用 3 脚跳线手动选择。

#### 3.2.1 实机实测结论与最终接线（以此为准）

按 3.2 节的 560 kΩ 方案实机接线后，喇叭**全程沙沙、发闷、人声小**；把 SD 直接接 3V3 后沙沙消失，只剩"大音量/强高音破音"。结合数据手册，最可能的解释是**560 kΩ 方案在本模块上没落在设计假设的 0.50 V，而是停在声道模式分界线上**：

| 计算（前提：该模块带 Adafruit 款 1 MΩ 上拉且未断开） | 数值 |
|---|---|
| SD 节点 = (3.3/560 + 5/1000) / (1/560 + 1/1000 + 1/100) | **≈ 0.85 V** |
| 该电压所属档位 | **0.77 – 1.4 V = 只出右声道，且紧贴 0.77 V 分界线** |

⇒ 任何耦合噪声都会让功放在“(L+R)/2”与“只出右声道”之间来回跳，听感就是**随音量变化的沙沙 + 发闷 + 人声小**（信号相关失真）；这也解释了“暂停时没有沙沙”（无信号就没有可失真的内容）。

**最终采用接线（本机实测通过）：**

| 项 | 取值 | 说明 |
|---|---|---|
| MAX98357A SD/MODE | **直接接 3V3** | 电压 > 1.4 V ⇒ 功放常开、只输出左声道；节点低阻，不会被噪声推着跳档 |
| ESP32 GPIO8 | **不用**（固件 -DPIN_AMP_SD=-1） | 不再驱动该脚；静音改由播放器内部淡出 + 输出全 0 帧承担 |
| GAIN | **悬空**（9 dB） | 实测值；若大音量仍破音，改成 **3 dB 档：GAIN 经 100 kΩ 接 Vin**（多 6 dB 余量）。注意官方增益表是"经 100 kΩ 接 GND = 15 dB、直接接 GND = 12 dB"，**把 GAIN 直接接 GND 会更响更破，别接错** |
| 声道处理 | **固件把 (L+R)/2 下混成单声道并复制到左右两槽** | SD 落哪一档都输出同一份完整混音 ⇒ “只出左声道”不丢内容（player.cpp 写 I2S 前） |
| 峰值余量 | **固件软限幅到 −6 dBFS** | 大音量/强高音不再硬削波（player.cpp 音量缩放之后） |

取舍：放弃“GPIO 硬件静音”换来稳定的声道模式；第 3.3 节的时钟不停、淡入淡出、欠载保护、去耦等措施继续生效。若日后一定要恢复硬件静音，正确做法是让 SD 稳定停在中间档（例如 **SD 经 1 MΩ 上拉到 3.3 V**，配内部 100 kΩ 下拉 ≈ 0.30 V，落在 0.16–0.77 V），而不是经 560 kΩ 接一个 3.3 V 的 GPIO（本机实测失败）。

### 3.3 七条反爆音措施（验收项 AC7 的保障）

1. **上电静音**：上电第一时间 GPIO8 = 低（功放关断），直到 I2S 就绪且缓冲预填不低于 64 KB 才拉高。
2. **I2S 时钟不停**：空闲时 DMA 持续输出全 0 数据。BCLK 停止会使 MAX98357A 进入异常状态并在恢复时爆音。
3. **淡入淡出**：每次播放/暂停/恢复/切歌，对 PCM 首尾各 **20 ms** 做线性斜坡。
4. **欠载保护**：缓冲水位低于 32 KB 时先淡出再输出静音帧，恢复时淡入。
5. **停止顺序**：先淡出 → 关功放（GPIO8 低）→ 停 I2S DMA。**顺序不可颠倒**。
6. **电源去耦**：VIN 就近 470 µF + 0.1 µF，功放地独立走线，星形单点接地。
7. **切歌去爆**：切歌必须先停流、清缓冲、重新定位后淡入，不允许在解码中途直接替换数据。

## 4. 系统架构与关键设计决策

### 4.1 分层与数据流

```
按键 / UI (STM32)
   |
   v
player.c 播放状态机 (STM32)
   |  CMD_* 控制指令  -->  USART2 1 Mbps  -->  ESP32 link_task
   |                                              |
   |                                         流控窗口决策
   |  <-- CMD_AUDIO_REQ {blocks} -----------------+
   v
audio_srv.c 非阻塞 SDIO-DMA 读取
   |  f_read 1024 B
   |  RESP_AUDIO {seq, len, data}
   +--> USART2 TX 环形缓冲 --> ESP32 512 KB PSRAM 环形缓冲
                                    |
                               Helix MP3 解码
                                    |  16 bit 立体声 PCM
                               I2S DMA --> MAX98357A --> 8 欧姆喇叭
```

### 4.2 关键设计决策表

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | **链路传 MP3 压缩码流，绝不传 PCM** | 320 kbps MP3 约 40 KB/s；解码后 PCM = 44.1k×16×2 = 176 KB/s，串口不可能承载 |
| D2 | **波特率定为 1 Mbps** | USART2 挂 APB1 42 MHz，BRR = 42 **整除、误差 0**；有效吞吐约 95 KB/s，对 40 KB/s 需求余量 2.4 倍。460800 仅 46 KB/s，余量不足必然爆音 |
| D3 | **保留 2 Mbps 升级路径** | BRR = 21 同样整除误差 0；仅在 1 Mbps 实测误码率不达标时才启用 |
| D4 | **ESP32 主动拉取（pull）流控** | STM32 只在收到请求后才发送，**构造上不可能溢出** ESP32 接收缓冲；无需 ACK、无需重传 |
| D5 | **信用窗口算法** | win = clamp((目标水位 − 当前水位) / 块大小, 0, 64)；在途未完成请求数小于 win 时补发请求。水位高时自动停发，水位低时自动加速，无需人工调参 |
| D6 | **帧协议沿用 AA55 同步头，CRC-8 升级为 CRC-16/CCITT-FALSE** | 1024 B 长帧下 CRC-8 漏检率过高（1/256）；CRC-16/CCITT-FALSE 漏检率约为 1/65536，成本仅多 1 字节 |
| D7 | **STM32 侧用非阻塞状态机 + SDIO DMA + ping-pong 双缓冲** | 旧工程注释已记录教训："主循环里不能有阻塞操作"。SDIO 读 1 KB 若阻塞可达 1 ms 以上，会拖慢 UI 与链路 |
| D8 | **ESP32 侧用 FreeRTOS 多任务** | Arduino 框架已含 FreeRTOS；link/dec 两任务解耦，解码阻塞不影响收帧。N16R8 有 8 MB PSRAM 与 512 KB SRAM，资源充裕 |
| D9 | **解码器选 Helix MP3** | 定点运算、内存占用小、单文件易移植、无外部依赖；ESP-ADF 需把工程从 Arduino 改为 ESP-IDF，改动过大；libmad 内存占用高 |
| D10 | **输出统一 44.1/48 kHz、16 bit、立体声** | 与计划书一致；采样率由 MP3 帧头自适应；单声道下混由 MAX98357A 硬件完成（见 3.2） |
| D11 | **音频块 1024 B** | 帧总长 1032 B，@1 Mbps 用时 10.3 ms，链路占空比 41%；块再大会增加延迟与缓冲压力，再小则开销上升 |
| D12 | **环形缓冲尺寸** | STM32：TX 4096 B、RX 1024 B；ESP32：RX 8192 B、播放缓冲 512 KB。旧工程 TX 只有 2048 B 且发送函数在空间不足时整帧丢弃，必须扩 |
| D13 | **范围控制：P1 不做歌词与真实封面** | 滚动歌词需 .lrc 解析、真实封面需 JPEG 解码器，均属额外子系统。设计稿中的封面区域 P1 用图标占位 |

## 5. 板间通信协议规范

### 5.1 帧格式

```
+--------+--------+--------+--------+--------+---------+---------+--------+
| 0xAA   | 0x55   | TYPE   | LEN_LO | LEN_HI | PAYLOAD | CRC_LO  | CRC_HI |
+--------+--------+--------+--------+--------+---------+---------+--------+
  同步头(2B)          类型(1B)  长度(2B,小端)   载荷(N)   CRC16(2B,小端)
```

- **CRC-16/CCITT-FALSE**：多项式 0x1021，初值 0xFFFF，输入输出不反转，结果不异或。校验范围 = TYPE + LEN_LO + LEN_HI + PAYLOAD。
- **最大载荷**：1024 B（音频块）。协议层接收缓冲按 1032 B 设计。
- **字节序**：小端。
- **重同步**：接收端在字节流中扫描 0xAA 0x55；帧内出现 0xAA55 不影响，因为变长帧必须 CRC 校验通过才被接受，否则整帧丢弃并继续扫描。

### 5.2 类型码表

**ESP32 → STM32（0x1x，请求/命令）**

| 类型码 | 名称 | 载荷 | 说明 |
|---|---|---|---|
| 0x10 | CMD_PLAY | track:u16 | 播放第 track 首 |
| 0x11 | CMD_PAUSE | — | 暂停 |
| 0x12 | CMD_RESUME | — | 恢复 |
| 0x13 | CMD_NEXT | — | 下一曲 |
| 0x14 | CMD_PREV | — | 上一曲 |
| 0x15 | CMD_STOP | — | 停止 |
| 0x16 | CMD_VOL | vol:u8 | 音量 0–100 |
| 0x17 | CMD_MODE | mode:u8 | 0 列表循环 / 1 单曲循环 / 2 随机 |
| 0x18 | CMD_SEEK | ms:u32 | 定位（P2） |
| 0x19 | **CMD_AUDIO_REQ** | blocks:u16 | **信用请求：再给 blocks 块** |
| 0x1A | CMD_LIST_REQ | from:u16, count:u16 | 请求曲目列表分页 |
| 0x1B | CMD_PING | tick:u32 | 心跳 |
| 0x1C | **CMD_SYNC_POS** | track:u16, offset:u32, seq:u32 | **重同步：定位到流内偏移并重置序号** |

**STM32 → ESP32（0x2x，应答/数据）**

| 类型码 | 名称 | 载荷 | 说明 |
|---|---|---|---|
| 0x20 | **RESP_AUDIO** | seq:u32, len:u16, data[len] | **音频数据块** |
| 0x21 | RESP_STATE | track:u16, total:u16, state:u8, vol:u8, mode:u8 | 播放状态 |
| 0x22 | RESP_TIME | ms:u32, total_ms:u32 | 进度与总时长 |
| 0x23 | RESP_LIST | index:u16, total:u16, name[64] | 曲目列表项 |
| 0x24 | RESP_END | track:u16, reason:u8 | 流结束（自动切歌） |
| 0x25 | RESP_PONG | tick:u32, drops:u16 | 心跳应答 |
| 0x26 | RESP_ACK | cmd:u8, status:u8 | 命令应答 |

### 5.3 信用窗口流控（核心机制）

**ESP32 侧状态**：fill（缓冲已填字节）、cap = 512 KB、target = 384 KB、inflight（已发出但未收到的块数）。

**每轮循环执行**：

```
win = clamp((target - fill) / 1024, 0, 64)
if (inflight < win) {
    blocks = min(win - inflight, 16)
    send CMD_AUDIO_REQ { blocks }
    inflight += blocks
}
```

**STM32 侧状态**：pending（待发送块数）、next_seq。

```
收到 CMD_AUDIO_REQ:  pending += blocks

状态机循环:
    while (pending > 0 && TX 环形缓冲空间足够) {
        从 SD 读 1024 B  ->  组 RESP_AUDIO { seq = next_seq++, len, data }
        pending--
    }
```

**性质**：
- ESP32 缓冲接近满时 win 归 0，自动停止请求，**不需要任何人工限速**。
- 缓冲为空时 win = 64，链路立刻满速填充，**启动快**。
- 因为 STM32 严格按请求发送，**接收端永远不会溢出**，从根上消除丢包。

### 5.4 错误恢复

| 故障 | 检测方式 | 处置 |
|---|---|---|
| CRC 校验失败 | 帧尾 CRC 不匹配 | 丢弃该帧，继续扫描 0xAA55 重新同步 |
| 音频块序号空洞 | resp.seq 不等于 expected_seq | ESP32 停止解码、清空缓冲、发 CMD_SYNC_POS{track, offset = 已消耗字节偏移, seq} 重开流 |
| 链路静默 | STM32 侧 2 s 无任何请求 | 停止读卡，进入 IDLE，UI 显示"音频模块未连接" |
| 链路静默 | ESP32 侧 1 s 无数据 | 重发 CMD_PING，连续 3 次无应答则复位链路状态 |
| 对端未上电 | 上电握手 | STM32 独立运行完整 UI/按键/列表功能，只是无声 |

## 6. 存储与播放列表（STM32）

### 6.1 FatFS 配置

| 配置项 | 取值 | 理由 |
|---|---|---|
| _FS_TINY | 1 | 减小 FIL 结构，省 RAM |
| _USE_LFN | 3 | 静态 LFN 缓冲，避免占用栈 |
| _CODE_PAGE | 936 | 简体中文 GBK，与字库编码一致 |
| _VOLUMES | 1 | 只用 SD 卡 |
| _MAX_SS | 512 | 不带 4 KB 扇区卡 |
| _USE_MKFS / _USE_LABEL | 0 | 不需要 |
| _FS_REENTRANT | 0 | 单任务访问 FatFS，无需加锁 |

**必须一致**：FatFS 代码页 936 与 TFT 字库编码必须同为 GBK，否则全部中文名显示为乱码。这是最容易被忽略的一致性问题。

### 6.2 目录扫描

- 优先扫描 /MUSIC 目录；不存在则扫描根目录。
- 匹配 .mp3（大小写不敏感）；跳过子目录、隐藏文件、0 字节文件。
- 上限 300 首；每首存 64 B 文件名 + 4 B 大小。
- **自然排序**：文件名中的数字段按数值比较，保证 01、02、…、10 顺序正确（纯字典序会把 10 排在 2 之前）。
- 超长文件名截断并追加省略号。
- 坏文件（打开失败、ID3 头异常大）跳过并记入错误计数。

### 6.3 SDIO 非阻塞读取（关键实现）

```
状态机: IDLE -> DMA_ISSUED -> WAIT_DONE -> SEND -> IDLE

IDLE        : pending > 0 且有空闲块缓冲 -> 配置 SDIO DMA，
              发起 SDIO_ReadMultiBlocks(2 扇区)，立即返回不等待
DMA_ISSUED  : 主循环继续跑 UI / 按键 / 协议
WAIT_DONE   : 下一个 1 ms 节拍检查 DMA 完成标志与 SDIO_FLAG_DBCKEND
SEND        : 把完成的块组帧写入 USART2 TX 环形缓冲，释放该块
```

- **ping-pong 双缓冲**：一块在从 SD 读取时，另一块在等待/发送，吞吐翻倍。
- **每块 2 扇区（1 KB）**：SDIO @24 MHz 下理论 341 µs 加卡访问延迟，典型小于 1 ms。
- **降级路径**：T1 阶段可先用阻塞式 f_read 打通功能，T2 阶段再替换为非阻塞状态机。功能与性能解耦，降低风险。

## 8. 音频子系统（ESP32-S3）

### 8.1 任务划分（FreeRTOS）

| 任务 | 优先级 | 职责 |
|---|---|---|
| link_task | 5 | 串口收帧、协议解析、流控窗口决策、命令分发 |
| dec_task | 4 | 从 PSRAM 缓冲取码流，Helix 解码，音量，淡入淡出，写 I2S |
| net_task | 2（P2） | WiFi / Web 控制 |
| loop() | 1 | Arduino 默认任务：状态灯、调试输出 |

单生产者（link_task 写缓冲）单消费者（dec_task 读缓冲），用一把互斥锁保护读写指针，避免优先级反转。

### 8.2 缓冲与内存

| 对象 | 大小 | 分配方式 |
|---|---|---|
| 播放环形缓冲 | 512 KB | PSRAM，heap_caps_malloc(MALLOC_CAP_SPIRAM) |
| 串口 RX 缓冲 | 8192 B | Serial1.setRxBufferSize |
| 解码输入工作区 | 4 KB | 内部 SRAM |
| 解码输出 PCM | 4608 B（1152 采样 × 2ch × 2B） | 内部 SRAM |
| I2S DMA | 6 × 256 帧 | 驱动内部 |

**注意**：N16R8 的 PSRAM 必须在 platformio.ini 中保持 qio_opi 加 -DBOARD_HAS_PSRAM，否则 PSRAM 不可用、512 KB 分配失败。

### 8.3 关键实现点

- **采样率自适应**：读取 MP3 帧头得到采样率（32/44.1/48 kHz），动态重配 I2S。
- **音量**：0–100 映射为 Q15 增益，解码输出后逐采样相乘，无级可调。
- **欠载保护**：fill 低于 32 KB 时输出静音并淡出，恢复时淡入，同时 underrun 计数上报。
- **EOF**：RESP_END 或缓冲耗尽则按播放模式自动切下一曲。
- **上电顺序**：GPIO8 低（静音）→ I2S 初始化并持续输出 0 帧 → 预填缓冲不低于 64 KB → GPIO8 高（开启功放）。
- **日志口**：务必使用板载 CH340 的 USB-C 口（UART0，COM8，115200）。项目原有 platformio.ini 注释已警告：**不要**添加 build_unflags = -DARDUINO_USB_MODE=1，也不要定义 ARDUINO_USB_MODE=0 / ARDUINO_USB_CDC_ON_BOOT=1，否则会切到原生 USB 而 CH340 口看不到日志。
